# 校园食堂智能体项目规划

## 简介

本项目全名为《面向校园食堂经营的就餐数据分析与菜品优化智能体设计与实现》，仓库名定为 `canteen-agent`。项目面向食堂经营者，把就餐数据变成可执行的经营决策，覆盖「数据 → 分析 → 建议 → 采纳 → 追踪 → 复盘」的完整闭环。

项目定位是开源作品与简历项目：完整可运行、工程化齐全，规模控制在本人能逐模块讲清的程度。本文档约定目标、范围、选型与里程碑，技术细节见 [架构设计](architecture.md)。

## 项目定位

本项目不是「接个大模型问答」的演示，差异化在三点。

1. 决策闭环：智能体产出的每条建议都是工单，经人工审批、执行登记、效果归因后归档，形成 PDCA（计划-执行-检查-处理）循环。
2. 领域分析：内置菜品四象限、ABC 分类、备餐预测、多目标菜单优化等食堂经营算法，由大语言模型（LLM）智能体通过工具调用驱动。
3. 工程完整：认证、迁移、测试、CI（持续集成）、Docker、中文文档齐全，克隆即可运行。

## 功能范围

### 本期交付

1. 数据管理：模拟数据生成器、CSV（逗号分隔值文件）导入、列校验与错误行报告。
2. 经营看板：营收、客流、客单价、时段分布、档口排行。
3. 菜品分析：销量 × 毛利四象限、ABC 分类、滞销预警、评价标签与满意度、营养结构。
4. 需求预测：按菜品 × 日期 × 时段预测备餐量，与基线对比，输出 MAE（平均绝对误差）和 MAPE（平均绝对百分比误差）。
5. 菜单优化：按毛利、满意度、营养、浪费四个目标加权打分，产出汰换、保留、推广建议。
6. 智能体对话：工具调用过程可视，SSE（服务器推送事件）流式输出，无 Key 自动降级为规则模式。
7. 决策闭环：建议工单状态机、审批、执行登记、前后对比归因、复盘归档。
8. 经营周报：一键生成 Markdown 周报，汇总指标、预警与工单进展。
9. 系统管理：JWT（JSON Web Token）登录、角色权限、操作日志。

### 非目标

明确不做：真实支付与硬件对接、多租户 SaaS（软件即服务）、移动端、实时数仓、让模型生成自由 SQL。范围膨胀时先砍可选增强，不动闭环主线。

## 数据方案

默认使用模拟数据：2 个食堂、8 个档口、约 120 个菜品、180 天约 25 万单订单，配套评价、成本与浪费记录。生成器内置工作日与周末、考试周、季节和随机扰动因子，固定随机种子可复现，并在 README 明确标注「全部为模拟数据」。

同时提供订单、菜品、评价三类 CSV 导入模板。拿到脱敏真实数据后可直接替换，分析代码零改动。数据不含真实个人信息，开源无隐私风险。

## 技术选型

选型基于本机实测：Python 3.12.3、Node 24、Git 2.53；无 MSVC 编译器，依赖只选纯 wheel；Hugging Face 不可达，不依赖需下载权重的模型。

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 后端 | Python 3.12 + FastAPI + SQLAlchemy 2 + Alembic | 既定模板栈，生态契合数据分析与智能体 |
| 数据库 | SQLite（默认），PostgreSQL（可选） | 零配置起步，迁移与方言由 SQLAlchemy 屏蔽 |
| 分析 | pandas + statsmodels + 手写优化算法 | 霍尔特-温特斯预测开箱可用；优化手写保证可讲解 |
| 大模型 | OpenAI 兼容接口（智谱、DeepSeek、通义千问等），httpx 直连 | 不绑死厂商；无 Key 走规则降级 |
| 前端 | Vue 3 + Vite + TypeScript + Element Plus + ECharts + Pinia | 沿用 ChartPanel.vue 既定封装，类型即文档 |
| 测试 | pytest + httpx + Playwright（本机 Edge 无头） | 接口与 UI 都可断言 |
| 工程 | ruff + GitHub Actions + Docker Compose + MIT | 开源标准配置 |

## 质量与测试策略

- 后端：pytest 单元测试覆盖算法并固定种子，httpx 集成测试覆盖接口；负向用例同时断言状态码与错误消息，避免假通过。
- 智能体：工具契约测试校验入参 schema 与审计落库；降级模式有独立用例。
- 前端：Playwright 驱动本机 Edge 无头浏览器，断言关键交互并截图人工复核。
- 检查脚本先注入违规样本验证「会报警」，再用于正式检查；验证脚本一律写成文件，不内联。
- CI：ruff 检查、pytest、前端构建、gitleaks 密钥扫描。

## 开源发布计划

- 协议与文档：MIT 协议；中文 README 含架构图、快速开始、截图与模拟数据声明；附 CONTRIBUTING 与开发文档。
- 仓库卫生：`.env.example` 不含密钥；提交前跑 gitleaks；模拟数据进仓库，真实数据永不进仓库。
- 发布节奏：M6 完成后公开仓库，打 v0.1.0 标签，配 CI 徽章与 topics；后续按 issue 迭代。
- 简历配套：交付一页「项目讲解稿」，覆盖架构、闭环、算法与取舍，面试可直接用。

## 简历亮点写法

- 独立设计并实现食堂经营决策闭环智能体：编排 8 个领域工具，建议经审批、执行、归因后归档，区别于纯问答演示。
- 实现菜品四象限、备餐量预测与多目标菜单优化；预测以季节朴素法为基线做回测，优化结果可复现、可解释。
- 完整工程化：FastAPI + Vue 3 全栈、Alembic 迁移、pytest 与 Playwright 测试、GitHub Actions CI、Docker 部署，MIT 开源。

具体数字（误差、提升幅度）在 M3、M4 实测后回填，不预先编造。

## 风险与对策

| 风险 | 对策 |
| --- | --- |
| 拿不到真实数据 | 模拟生成器兜底，CSV 导入随时替换 |
| 没有 LLM Key | 规则降级全流程可用，Key 到位后一键切换 |
| 依赖需编译 | 只选纯 wheel；环境装在项目目录内 |
| 范围膨胀 | 非目标清单约束，里程碑验收可证伪 |
| 讲不清代码 | 模块一页纸 + ADR + 讲解稿，核心算法手写 |

## 已确认决策

1. 项目不兼作毕设，仅用于简历与开源，校园场景无约束冲突。
2. 全程使用模拟数据，CSV 导入口保留，拿到脱敏数据可随时替换。
3. 仓库名定为 `canteen-agent`。
4. 大模型接入智谱 AI：OpenAI 兼容端点，模型 `glm-4.5-flash`（实测可用；`glm-4.7-flash` 探测时 429 限流，可后续切换）。Key 只存本地 `.env`，不进仓库。
